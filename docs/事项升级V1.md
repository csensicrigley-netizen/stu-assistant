## 3. 用户操作流程

### 3.1 新建并确认

1. 在事项页点击“记一件事”。顶部输入框落下，自动聚焦并唤起键盘。
2. 输入要做的事并主动提交。输入框保持锚点，键盘收起，页面以柔边圆形遮罩展开。
3. 请求期间显示轻量加载过渡；成功后进入固定标题“建议”的结果页。
4. 在三天日历中查看当前批次与已缓存课程、个人安排和旧计划的相对位置。多事项通过编号独立选择。
5. 拖动、缩放或进入精确时间编辑；备注、优先级及提醒意图放在事件选项内。
6. 点击“确认”，当前批次一次原子保存。重复确认同一批次不产生重复记录，首条有日期时，首页定位到该日期。

用户尚未确认的识别结果只是草稿。返回或关闭不会把它悄悄写成已保存事项。网络失败会保留可重试的输入；手动记录是用户明确选择的路径，不用预设事件伪装模型结果。

### 3.2 日历中的直接操作

- 默认显示当前日期及前后一天，三列共用小时栏；自动按所选事项取景，时间尺度可双指缩放。
- 整个建议页固定在一屏。只有中间时间视窗上下平移，日期、输入和确认不会作为长表单滚走。
- 拖动当前草稿的时间段可以移动时间；横移到相邻日期列改变日期并保留时长；上下抓手分别调整开始、结束。
- 时间点和截止点用线与圆点表示；普通时间点可从空心抓手拉出时长，段收回可恢复为点，截止不会自动变成一小时时段。
- 松手吸附到五分钟刻度。第二根手指进入时转为缩放，撤销该手势内尚未确认的临时位移，剩余一指不继续误拖事件。
- 重叠事件并列，跨日时段按日裁剪显示；裁剪和最小视觉高度不修改真实时间。
- 长按空白或“未安排”入口可为当前事项主动添加时间；只有日期的截止不自动变成零点。

日历背景中的课程、已保存事项和旧计划是只读上下文。拖动及精确时间编辑针对当前新建批次，不等于已经实现了已保存事项编辑器。

### 3.3 查看、完成和学业查询

开发中间版曾把整行绑定为完成并隐藏已完成课程动态，PR #26 已纠正这项回归。完成圆圈和详情区域是两个独立目标。勾选后保留原行，以勾和划线表现状态；再次点击圆圈可取消完成。标题和箭头只展开/收起详情，不会修改完成状态。

本地事项详情展示已保存的时间、日期、备注及相关配置；课程动态详情展示同步结果中已有的课程、来源、截止、学校状态、正文和原站入口。缺失的正文、截止或学校状态不由客户端编造。仅日期的截止保持原日期精度，不展示内部排序补出的 `23:59`。

“学业”中分别进入考试安排、课程成绩；系统返回先回学业，再回事项。学业内部往返保留列表位置和详情状态。旧云计划请求期间阻止重复完成请求。本地事项更新不先清空整个列表，账号切换会隔离前一账号的页面状态和错误提示。

## 4. 已确定的设计规则

| 规则 | 当前落实 |
| --- | --- |
| 简单入口、渐进披露 | 一个新增入口；时间和事件选项原位切换；不常驻长表单或大量调整按钮 |
| 手机优先 | 竖向三天时间视窗；精确编辑中的日期、开始、结束同屏，编辑时“完成”替换“确认” |
| 连续反馈 | 约 1250ms 渐缓圆形展开；切日有方向性滑动；展开、收起和返回有过渡 |
| 快速数字可见 | 逐字位常驻；低频柔化弹入，快速变化保持不透明并带轻微模糊，停止后清晰落定 |
| 触感统一 | 提交按钮按下/松开两段反馈；时间平移跨次刻度触发 selection tick，至少间隔 80ms，不排队，沿用全局强度 |
| 圆角统一 | Kyant Shapes 连续圆角；圆形按钮宽高相等；嵌套轮廓与留白一起校正 |
| 边缘柔化 | 日历上下 56–96dp 两级模糊、轻微透镜色散和整层渐隐，中心保持清楚 |
| 背景隔离 | 玻璃按钮采样当前页底色，输入环境模糊单独取样；日历边缘只采样日历自身 |
| 全局顶部 | NPage 和滚动抽屉内容恢复 GPU 顶部渐进模糊；固定抽屉标题、关闭按钮保持清楚 |

顶部柔化此前位于未合入的旧分支，PR #26 恢复了实现内容；不代表该旧分支的所有提交均被合并。全局顶部柔化与新建日历自身的上下材质是两个独立组件。低版本降级、实现依据见[顶部 Soft Edge](顶部SoftEdge.md)。

## 5. 数据、推理和权限边界

新事项业务数据在设备本地，以已有 Keystore AES-GCM 和 AtomicFile 能力保存，按服务器和助手用户隔离。批次去重、确认时账号校验、退出保留和删除账号后的清理均由 Store 负责。

在线识别只在用户主动提交时发生，使用现有 STU 登录身份调用独立 `smart-calendar` 的 mobile 接口。自然语言理解是 Jev-only，确定性代码和 Duckling 负责时间处理；没有附加 LLM。Key 池解决负载、额度和限流可用性，系统用量治理负责上限和防滥用，两层职责分开。

新 mobile 推理入口不创建服务端预览或保存输入/结果等业务内容；服务保留其契约规定的访问和用量元数据。这项边界不意味着整个既有 STU 账号、校园采集、旧云计划系统已经全部迁为本地，也不能据此推断供应商的保留政策。

学校数据保持只读。课程动态的完成勾选只记在设备上，不会提交 MySTU 作业或更改学校状态。字段、接口示例、账号生命周期和模块职责详见[架构与接口](事项V1架构与接口.md)。

## 6. 当前明确未完成的能力

| 能力 | 当前边界 |
| --- | --- |
| 课程动态 Jev 分类 | 尚无 App 分类接入及专用后端分类路由；用户已明确下一轮再做 |
| 每个学校活动只识别一次的账本 | 尚未实现；不能把手动新建批次去重当成课程分类去重 |
| 已保存的新事项完整 CRUD | 当前可查看、完成/撤销；保存后的编辑、删除和重排入口尚未提供 |
| 设备提醒 | 保留提醒意图和配置，尚未接 OS 通知调度；选项内提示通知未启用 |
| 自动排期与冲突求解 | 展示时间上下文供用户调整；不承诺自动避开所有课程或求得全局最优安排 |
| 复杂重复规则及长期计划执行 | 不因保留字段就视为已展开或执行 |
| 新日历网页版 | 本轮是原生 Compose 首版，网页没有获得同等交互 |
| 全机型性能与手感 | 模拟器功能/像素验证不能替代各 OEM 真机帧率和马达体验 |

旧计划的 Store/API 兼容方法继续保留。旧事项 UI 的新建、删除、排序入口在本次整理之前就已不在实际路由上，不能把残留函数当作新版页面已交付能力。

## 7. 需求演进与已覆盖的旧方案

原始长对话和阶段规划用于追溯需求，最终以用户后续纠正和当前源码为准：

| 早期规划/候选 | 当前结论 |
| --- | --- |
| 新建从底部抽屉展开 | 用户明确改为顶部输入、原位展开结果，避开键盘与抽屉同时从底部升起 |
| 横向单行时间条 | 原型验证后改为默认竖向三天视图；拖动与时间精度语义保留 |
| 服务端 preview/日历主库/commit/outbox | 新 mobile 路径改为只推理，事项在设备本地保存；旧原型兼容接口不等于 App 主存储 |
| 另接 LLM 完成整句理解 | 已纠正为 Jev-only，不在 App 或后端悄悄加模型 |
| 路由承担成本控制 | 已明确拆成 Key 可用性路由和系统治理两层 |
| 所有学校活动直接算作业 | 当前明确为未分类课程动态，分类与一次识别账本留待下一轮 |
| 页面常驻解释、快捷加减按钮、多组字段 | 采用直接操作和按需编辑；固定“建议”“确认”，去掉重复返回按钮和常驻手势教学 |

原阶段规划里“尚无真实 Key”“前端尚未开始”等状态只代表当时时点。本说明没有把早期助手建议或未完成目标统一勾成已交付，也不把完整聊天、密钥和本机日志上传仓库。
