# 授权与边界（STU 事项助手）

> 建立时间：2026-10-29
> 这份文件的作用：把「谁授权、允许做什么、不做什么、怎么撤销」写在项目里。
> 任何接手的人（包括以后的我）改代码前先读这一页。

---

## 一、授权从哪里来

| 项 | 内容 |
|---|---|
| 授权人 | **账号本人**（在 App 绑定页亲手输入自己学号与密码的那位学生） |
| 授权动作 | 在绑定页输入本人的学校账号、密码；学校要求时，由本人在同一页输入**数盾动态令牌** |
| 授权范围 | **只读**本人账号在教务、MySTU、学校 OA 上本来就能看到的课表 / 作业 / 通知 / 成绩 |
| 授权目的 | 把这些信息按时间整理好，只展示给本人和设备本人授权的推送通道 |
| 授权留痕 | `users.student_id_h`（学号哈希）、`credentials_meta`（绑定时间与服务名）、`sync_runs`（每次读取的时间与结果码） |

App 里绑定页固定显示这一行，改版也不许删：

> **本人授权使用**：这里的账号密码由你本人输入，只用于替你读你自己的教务、MySTU 和学校 OA 通知……

## 二、允许做的

1. 用本人账号登录学校统一认证 / 教务 / MySTU / WebVPN；
2. 通过 WebVPN 读取本人可见的 OA 通知（每天最多 10 条）；
3. 把会话与（勾选记住时的）密码加密保存在**该用户自己的租户目录**里，用于会话过期后自动重连；
4. 用该用户自己登记的推送 token 给他本人发「有新通知 / 有新版本」的提醒；
5. 会话过期且学校要求令牌时，回到绑定页让**本人**输入动态令牌。

## 三、明确不做的

- ❌ 不登录任何**他人**账号，不代填、不代输、不转交凭据；
- ❌ 不猜解密码、不爆破、不绕过任何认证环节（验证码、动态令牌、扫码确认）；
- ❌ 不伪造令牌，不复用别人的会话 cookie，不把 A 的会话结果喂给 B（`collect_public_shared` 因此对带 vault 的读取直接绕开共享缓存）；
- ❌ 不向学校任何系统**写入 / 提交 / 修改**数据（不交作业、不签到、不缴费、不报名、不提交报修）；
- ❌ 不代签到、不代缴费、不在 App 内转载树洞内容（见 `交接文档.md` §5「不要做」）；
- ❌ 不把密码、令牌、cookie 写进日志、写进前端、写进推送内容；
- ❌ 不以环境变量切换租户、不共用同一份会话目录。

## 四、凭据放在哪

| 内容 | 位置 | 说明 |
|---|---|---|
| 学校账号 / 密码 | 租户自己的 keyring：`<tenant>/credentials.enc`（由 `<tenant>/master.key` 包裹） | 只在用户勾选「记住密码」时写入；不写数据库、不写日志 |
| 各系统登录会话 | `<tenant>/sessions/<service>.bin` | 加密存储；**进程重启不丢**，所以重启后台不需要用户重登 |
| 数盾动态令牌 | **不保存** | 每次学校要求时由本人当场输入，输入完即丢弃 |
| 学号 | 只存哈希 `users.student_id_h` | 用于「同一学号不重复占用」的校验 |

租户目录由 `tenancy.py` 的 `tenant_scope(user_id)` 隔离，路径按 user_id 派生；
`purge_tenant()` 会连同会话与凭据一起删除。

## 五、撤销方式

| 想撤销 | 怎么做 |
|---|---|
| 停止自动重连 | 在「我」里关掉「记住密码」，或清除凭据 |
| 彻底断开学校账号 | 「我」→ 断开连接（`POST /v1/relogin` 之外的登出路径），随后可用 `DELETE /v1/account` |
| 删除全部数据 | `DELETE /v1/account` → `purge_tenant()` + 删除用户行 |
| 运维侧清理某个租户 | 停服务后删 `$STU_APP_HOME/tenants/<user_id>` 整个目录 |

## 六、给用户的一句话

这个 App 只借你自己那双眼睛，看你自己能看的东西。
账号密码和动态令牌永远由你自己输；它不会替你签到、替你交作业，也不会把你的东西挪到别人的空间里。

## 七、代码里的落点（改这里要同时改这份文件）

| 位置 | 管什么 |
|---|---|
| `backend/app/bind.py` | 绑定服务清单 `BINDABLE`、令牌挑战通道 `challenge(kind=totp)` |
| `backend/app/relogin.py` | 用租户已存密码静默重登（拿不到令牌就停下来问人） |
| `backend/app/collectors.py` | OA 通知只读、每天 10 条、失败只降级不伪造 |
| `backend/app/sync.py` | 每个源用哪个会话重登（`SESSION_FOR`），public → webvpn |
| `backend/app/version.py` | 版本登记与「新版本推给旧客户端」 |
| `web/src/screens/Welcome.tsx` | 绑定页那句「本人授权使用」 |

## 八、数盾动态口令：本人输、不保存、不代输（2026-10-29 补充）

| 约定 | 落地方式 |
|---|---|
| **必须本人输** | 学校要求令牌时，登录流程进入 `waiting_input`，界面弹出输入框（`challenge.kind === "totp"`），后端只等这一次输入；没有人工输入就停在这一步，不会绕过去 |
| **不保存口令** | 口令只在 `bind.py` 的 `_Interaction.code()` 里存活一次，回给学校换会话后立即丢弃；数据库、日志、keyring 里都没有这 6 位数字 |
| **不代输** | 服务器没有任何地方能自己生成/猜测口令；`relogin` 遇到要令牌时**主动停下**并返回 need_input，而不是硬试 |
| **不转发** | 口令不进推送、不进 `/v1/status` 的 detail、不写进任何缓存文件 |
| **授权留痕** | `consents` 表只记 `user_id / scope / at / version`，不记 IP、设备、生物特征 |
| **可撤回** | `DELETE /v1/consent?scope=oa` → 立刻停读；`DELETE /v1/account` → 连租户目录一起删 |

两道门禁的顺序（缺一不可）：

```
1. 本人点「本人授权」→ POST /v1/consent        （没有这行 → 连 WebVPN 都 403）
2. 本人在绑定页输数盾口令 → bind webvpn 成功    （没有会话 → OA 一次都不读）
```

实测（TestClient）：

```
未授权连 webvpn : 403
只连教务        : 200
授权后连 webvpn : 200
撤销授权后再连  : 403
```

**给爸爸的那句**：授权是学生自己点的、口令是学生自己输的、留存只有时间戳——这三条都在代码和界面里写着，不是口头承诺。
