# STU 事项助手 · 动效与性能优化方案

> 一句话结论：**动画只碰 `transform` / `opacity`，页面按需分包，磨砂只留在便宜的地方。**
> 这份文档里的数字都是在 `web/` 下 `npm run build` 的真实产出，不是估算；每条改动都写明
> 落点文件与理由，包括「想过但故意不做」的几条。

---

## 0. 两份参考，各抄了什么

参考调研对象：`motionsites.org/zh/prompts/design-world`（一批设计提示词合集）与
`github.com/GazizVR/BirGram`（一个把页面切换做得很顺的 Telegram 风格前端）。
**只抄手法，不抄皮肤** —— 我们的色板、字体、间距体系保持原样。

| 参考里的手法 | 观察到的东西 | 本项目的落点 | 代码位置 |
|---|---|---|---|
| 页面切换不是交叉溶解 | 旧页极快淡出（≈120ms），新页用弹簧落位；**同时进行**，中间不留空白 | `AnimatePresence mode="popLayout"` + `startTransition` | `web/src/App.tsx`、`web/src/lib/motion.ts`（`PAGE_IN` / `PAGE_OUT`） |
| 指示器是"同一颗药丸滑过去" | 归属同一个 `layoutId`，位置由共享布局算，不是各自重画 | tab 指示器、分段控件、导入方式切换 | `components/TabBar.tsx`、`components/Segmented.tsx`、`screens/Import.tsx` |
| 列表逐项落位，带微延迟 | 每项延迟 20–40ms，最多叠到 120ms 就封顶，否则后面几项像在等人 | `rise(i)` | `web/src/lib/motion.ts` |
| 按下有"被抓一下"的反馈 | 缩放 0.965 下去，松手带一点点回弹（低阻尼弹簧） | `PRESS` + `TAP`，高频反馈走纯 CSS 不惊动 React | `motion.ts`、`app.css` 的 `--ease-jelly` 段 |
| 固定底栏磨砂 | 半透明 + 背景模糊 | 保留观感但把成本压下来（见 §2.4） | `app.css` `.tabbar` |
| 大留白 + 大字重 + 克制的入场 | 内容自己安静地出现，不抢注意力 | `rise()` 起点 `y:10 / scale:0.985`，全程无位移夸张 | `motion.ts` |

## 1. 动效词汇表（`web/src/lib/motion.ts`）

全 App 只允许用下面这几档，不要在页面里手写新的弹簧参数 —— 手感一旦分裂，用户第一眼就觉得"廉价"。

| 档位 | 参数 | 用在哪 |
|---|---|---|
| `GLIDE` | spring 260 / 30 / 1 | 长距离位移，不允许过冲 |
| `SPRING` | spring 420 / 26 / 0.9 | 交互反馈的主力档 |
| `JELLY` | spring 300 / 16 / 0.85 | 有可见回弹：按下、吸附、指示器 |
| `JELLY_SOFT` | spring 240 / 20 / 0.9 | 大标题、整页进出，只留一点点回弹 |
| `SETTLE` | spring 180 / 24 / 1 | 长列表整体落位，肉眼看不出过冲 |
| `PRESS` | scale 0.965 | 按下瞬间 |
| `TAP` | spring 320 / 18 / 0.7 | 松手弹回 |
| `PAGE_IN` / `PAGE_OUT` | spring 300 / 24 / 0.9 ｜ 0.12s ease-out | 切页进 / 退（退场没人看，快才不卡） |
| `PILL` | spring 380 / 17 / 0.8 | tab 药丸、分段控件 |
| `SHEET` | spring 360 / 30 / 0.9 | 底部弹层吸上来 |
| `MAGNET_RANGE` / `MAGNET_PULL` | 90px / 7px | 引力吸附的最大位移与拉伸量 |

**纪律**：这里不许出现 `width` / `height` / `box-shadow` / `filter` 的动画 —— 那几项会触发布局或重绘，
正是"一卡一卡"的来源。

## 2. 性能：这次真正改了的六条

### 2.1 首屏拆包（最大的一项）

**问题**：改之前是单个入口包 `index.js 548.45 kB / gzip 177.86 kB`。七张页面全部打进主包，
打开 App 就得把"我的""校园""导入"这些可能一整天都不看的代码一起下载 + 解析。

**改法**（`web/vite.config.ts` + `web/src/App.tsx`）：

1. `manualChunks` 把 `react` / `motion` / 其它依赖拆成三个 vendor 包 —— 这条主要不是为体积，
   是为**缓存**：改一个页面只让业务包换哈希，vendor 包还留在 WebView 缓存里，一次更新的下载量能少一大半。
2. 除「今天」外的六张页面改成 `lazy()`；`Suspense` 放在 `motion.main` **里面**，
   这样页面容器的弹簧照旧跑，只是内容晚一两帧到；fallback 是等高骨架，避免落地时高度跳变
   （高度跳变比空白更像"卡"）。
3. 首帧画完后 `setTimeout(..., 240)` 把六块 chunk 全部预取。人不点标签也在后台下完，
   真正点的时候已经在缓存里 —— 平时看不到切换等待。

**实测（同一次 `npm run build`）**：

| 产物 | 改前 | 改后 |
|---|---|---|
| 入口 `index.js` | 548.45 kB / 177.86 gzip | **105.49 kB / 37.02 gzip** |
| `vendor-react.js` | —（在主包里） | 221.72 kB / 68.98 |
| `vendor-motion.js` | —（在主包里） | 127.49 kB / 41.89 |
| `vendor.js` | — | 10.37 kB / 4.22 |
| 首屏必须下载 | **177.86 gzip** | **152.11 gzip** |
| 六张页面 | 都在主包里 | 独立 87.29 kB / 33.60 gzip，首屏之后才下 |

净效果：**首屏少 25.75 kB（−14.5%）压缩体积**，另外 87.29 kB 的页面代码从"打开就付"变成
"用到才付"。代价是多了 6 个 chunk 的边界开销，全部页面加起来比原来大约 3.91 kB —— 值得。

### 2.2 切页：`popLayout` + `startTransition`

`mode="wait"` 会先等旧页退干净再让新页进，中间那一下空白就是"卡"的第一来源。
`popLayout` 让两件事同时发生：旧页 120ms 纯透明度退场，新页同时弹簧落位。

`go()` 里的 `setTab` 包在 `startTransition` 里：新页面的重渲染是"可打断的低优先级工作"，
React 会让动画的第一帧先跑，列表慢慢补上；同步做的话动画第一帧会被渲染任务挤掉，
手指看到的就是"先定住，再跳一下"。

### 2.3 合成层：只动 `transform` / `opacity`

`.page` 常驻 `will-change: transform, opacity` + `backface-visibility: hidden`
（`app.css` 的「高刷与手感」段）。这是一个有意的取舍：常驻提升能省掉每次切页的重新提升与栅格化，
代价是内存里常驻一处合成层。`prefers-reduced-motion: reduce` 下自动退回 `will-change: auto`。

「上课中」卡片那条扫光（`.now--live::after`）是纯 `transform` 的 `translateX` 循环，
`will-change: transform` + `backface-visibility: hidden` 把它钉在合成层里跑，不进主线程。

### 2.4 磨砂：全 App 唯一"每帧都要重算"的属性

`.tabbar` 是 `position: fixed` + 半透明 + `backdrop-filter`。底下的内容每滚一像素，
这一条就要重新采样一次 —— 这是整个 App 唯一一处不可避免的每帧 GPU 成本。

三处一起降本（`app.css` `.tabbar`、`styles/tokens.css` `--bar-bg`）：

| 项 | 改前 | 改后 | 理由 |
|---|---|---|---|
| 模糊半径 | `blur(20px)` | `blur(14px)` | 半径是主要成本；14px 与 20px 观感差别几乎看不出，采样量差一截 |
| 背景不透明度 | `0.86` | `0.90` | 底更实一点，需要模糊掉的细节就少一点 |
| 不支持时 | 留一层半透明糊 | `@supports not (...)` 退回不透明 `--surface` | 老 WebView 别留一块糊住的底栏 |

真要彻底零成本，就把 `backdrop-filter` 两行删掉、`--bar-bg` 提到 `0.96` —— 观感会从"磨砂"变"实心"，
这是唯一的取舍点，留着方便回退。

### 2.5 列表：`layout="position"`

`screens/Plan.tsx` 的待办条目原来写 `layout={!reduced}`。默认的 `layout` 会为每一项实时校正
尺寸与缩放，一条列表几十项时每秒都要量一遍所有盒子。这些条目只会"换位置"、不变尺寸，
改成 `layout="position"` 后 motion 只需记住 `translate`。`prefers-reduced-motion` 下仍是 `false`。

### 2.6 已经在做、但容易被后来者改坏的四条

| 项 | 值 | 别动的原因 |
|---|---|---|
| `-webkit-tap-highlight-color` | `transparent` | 否则每次点按闪一块灰，比任何动画都显廉价 |
| `touch-action` | `manipulation` | 去掉 300ms 双击缩放等待，点按才跟手 |
| `scroll-behavior: smooth` | 只在 `prefers-reduced-motion: no-preference` 下 | 晕动症用户要能关掉 |
| `overscroll-behavior: contain` | 弹层滚动区 | 否则滑到底会把整页带着一起滚（"橡皮筋"抖动） |

## 3. 想过但故意不做的（附理由，免得下次有人再提一遍）

| 想法 | 为什么不做 |
|---|---|
| 给长列表加 `content-visibility: auto` | 屏外内容跳过布局，听起来很香；但它会让元素高度变成估算值，弹层的定位测量和滚动锚定会抖。收益不确定、风险确定，不做。 |
| 用 JS 监听 `scroll` 做视差 / 进度条 | 主线程每帧回调，在 Android WebView 上比 CSS 动画贵一个量级。真要视差用 `animation-timeline: scroll()`，但那要求较新的 Chromium。 |
| 引入第二套动画库（GSAP / anime.js） | `motion/react` 已经覆盖全部需求，多一套 = 多一份解析与两份不同的手感。 |
| 常驻骨架屏 / 首屏 loading 图 | 首屏已经在 240ms 内出内容，常驻骨架只会让"其实已经好了"的时间看起来更长。骨架只出现在真正会等的地方（`Suspense` fallback）。 |
| 把所有页面再拆成"组件级"分包 | 再拆下去每个 chunk 只有十几 kB，HTTP 请求与 chunk 边界开销就盖过收益了。 |

## 4. 验证清单

```powershell
cd web
npm run typecheck          # tsc -b --noEmit，必须 0 错误
npm run build              # 观察 dist/assets 下是不是 4 个 vendor + 6 个页面 chunk
```

构建后应看到（文件名哈希会变，数量与量级不变）：

```
dist/assets/index-*.js             ~105 kB
dist/assets/vendor-react-*.js      ~222 kB
dist/assets/vendor-motion-*.js     ~127 kB
dist/assets/vendor-*.js             ~10 kB
dist/assets/{Plan,Week,Study,Campus,Me,Import}-*.js   6.5 ~ 24 kB
```

`dist/index.html` 里入口脚本与三条 `modulepreload` 都必须是 `./assets/...` 相对路径 ——
相对路径才能同时适配域名根、子路径、以及 App 内的 `https://localhost`。

真机上看四件事：

1. 冷启动到「今天」出内容，不该有白屏超过半秒；
2. 连点五个标签来回切，药丸指示器要跟着手指滑，不是跳；
3. 课表页快速上下滚，底栏磨砂不该掉帧（这一条是 §2.4 的唯一验收点）；
4. 系统开「减弱动态效果」后，所有动画退成 ≤120ms 的淡入淡出，扫光停下。
