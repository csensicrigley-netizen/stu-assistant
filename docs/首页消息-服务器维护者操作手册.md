# 首页弹窗：交给服务器维护者的操作手册

本手册供维护正式 API 服务器的另一位仓库作者操作。客户端开发者交付代码与安装包，服务器维护者部署后端并管理公告 JSON。客户端不会写入服务器配置，也不需要服务器管理凭据。

## 先部署一次功能，之后只改内容

首次启用需要同时具备两项：

1. 正式后端部署包含 `app/announcements.py`、`app/announcements.example.json` 以及路由注册的新代码。按现有发布流程更新服务器包；标准安装脚本是 `sudo bash stu-assistant-server/deploy/install.sh --no-proxy`，保留原有反向代理及数据目录。首次部署代码会重启服务。
2. 用户安装包含首页消息功能的新版 APK；网页用户使用对应新版前端。旧 APK 不会因为服务器多了 JSON 而自动获得弹窗功能。

这是本次开发新增的能力，不能把旧正式版本当成已经支持。合入并发布新版后，修改标题、正文、图片、按钮、动画选项或展示频次，**不需要重新打 APK，也不需要重启后端**。动画选项限于客户端已经内置的五款；增加全新的动画素材或改变布局仍要更新客户端。

先在 API 服务器验证路由（这里不是 APK 下载站或纯静态站）：

```bash
curl -fsS 'http://127.0.0.1:8100/v1/announcements?platform=android' | python3 -m json.tool
```

应返回 `{"announcements": [...]}`。404 表示后端尚未部署此功能；返回 HTML 通常表示域名或反向代理指向了静态站。

## 第一次建立配置

以下路径对应仓库标准安装。若服务用了别的路径，先核对 `/etc/stu-assistant.env` 中的 `STU_APP_HOME`；若设置了 `STU_APP_ANNOUNCEMENTS_FILE`，以该文件路径为准。服务运行账号默认 `stu-assistant`。

```bash
# 仅第一次复制，不覆盖维护者已经写好的消息。
sudo test -e /var/lib/stu-assistant/announcements.json || \
  sudo install -o stu-assistant -g stu-assistant -m 640 \
    /opt/stu-assistant/app/announcements.example.json \
    /var/lib/stu-assistant/announcements.json
```

正式配置在 `/var/lib/stu-assistant/announcements.json`，属于持久化数据；不要把日常编辑写进 `/opt/stu-assistant/app/announcements.example.json`，程序升级会覆盖后者。未建立默认配置文件时会展示内置 GitHub 来信；要停用请写关闭配置，不要删除文件。

## 日常发布：编辑草稿、校验、替换

```bash
sudo cp -p /var/lib/stu-assistant/announcements.json \
  /var/lib/stu-assistant/announcements.next.json
sudoedit /var/lib/stu-assistant/announcements.next.json

# 只有校验成功才替换，避免用户读到编辑了一半的文件。
cd /opt/stu-assistant
sudo venv/bin/python -m app.announcements --check /var/lib/stu-assistant/announcements.next.json && \
  sudo chown stu-assistant:stu-assistant /var/lib/stu-assistant/announcements.next.json && \
  sudo chmod 640 /var/lib/stu-assistant/announcements.next.json && \
  sudo mv -T /var/lib/stu-assistant/announcements.next.json /var/lib/stu-assistant/announcements.json
```

例如更新 GitHub 来信，让已经看过第 1 版的用户再收到：

```json
{
  "enabled": true,
  "announcements": [{
    "id": "github-star",
    "revision": 2,
    "eyebrow": "开发者来信",
    "title": "给小助手一颗 Star",
    "body": "如果小助手帮到了你，欢迎来 GitHub 点亮一颗 Star。\n也欢迎提交 Issue 反馈问题、分享想法，或贡献 PR，一起让它变得更好。",
    "image_url": null,
    "image_alt": "",
    "action_label": "去 GitHub 点亮 Star",
    "action_url": "https://github.com/csensicrigley-netizen/stu-assistant",
    "effects": ["star-struck", "heart-on-fire", "folded-hands", "party-popper", "keycap-one-6"],
    "display": "once",
    "platforms": ["android", "web"]
  }]
}
```

- 修改错字但不想再次打扰已读用户：保持 `id` 和 `revision`。
- 需要让已读用户收到更新：同一 `id` 的 `revision` 加一。
- 发布另一条公告：使用新的 `id`；同一配置可以包含多条，优先级由 `priority` 决定。
- `display: "once"` 每个版本只展示一次；`daily` 每天最多一次；`always` 每次打开最多一次。通常用 `once`。
- 维护通知不需要庆祝效果：设 `effects: []`。纯文字通知不需要外链：设 `action_url: null`。

## 配图

图片可以使用公开 HTTPS 地址，也可以放在 API 服务器的数据目录：

```bash
sudo install -d -o stu-assistant -g stu-assistant -m 750 /var/lib/stu-assistant/announcements-assets
sudo install -o stu-assistant -g stu-assistant -m 640 ./welcome-v2.webp \
  /var/lib/stu-assistant/announcements-assets/welcome-v2.webp
```

在草稿中设置 `"image_url": "/v1/announcements/assets/welcome-v2.webp"`、`"image_alt": "欢迎使用 STU 事项助手"`，然后按上面的校验流程发布。替换海报时推荐使用新文件名，同时按是否需要再次展示决定要不要提高 `revision`。这些图片和文案是公开内容。

## 用户什么时候收到

后端在**每次请求**时读磁盘上的最新 JSON，响应带 `Cache-Control: no-store`。App 首次进入「今天」以及从后台回到前台、首页可展示时检查；网页在进入首页、页面重新可见时检查。关闭后在同一次打开中切换标签不会连续弹出多条。

用户正在阅读的弹窗不会被后台修改突然替换。用户下次回到前台／重新打开时按最新配置与已读记录选择消息。用户停留在前台不操作时不做定时轮询；App 完全关闭时不会收到系统推送。离线或请求失败时跳过，下次打开再检查。

所以“热更新”指**内容由服务器控制，后续打开不必升级 APK 即可读到新内容**，不是远程更新 App 代码，也不是强行打断当前页面的即时推送。

## 验证与停用

先把下面的域名换成客户端实际连接的 API 域名，再检查外网结果：

```bash
curl -i 'https://API域名/v1/announcements?platform=android'
curl -i 'https://API域名/v1/announcements?platform=web'
```

确认返回最新 `id`、`revision`、内容及 `Cache-Control: no-store`。若启用了版本范围，查询须加 `&version_code=用户APK的实际versionCode`；不带版本的请求不会返回这类消息。CDN、反向代理应跳过 `/v1/announcements` 和 `/v1/announcements/assets/` 的缓存，不能忽略源站的 `no-store`。

然后用新版 App 连接该 API，切回桌面再回到「今天」。要测试已读消息，增加 `revision`，不必清除用户数据。

停用时把草稿改成下面内容，校验并替换：

```json
{"enabled": false, "announcements": []}
```

下一次检查不再展示；已经打开的卡片由用户正常关闭。

排查：

| 现象 | 优先检查 |
| --- | --- |
| 404／返回 HTML | 正式后端未更新，或请求落到静态站／错误域名。 |
| API 内容还是旧的 | 编辑的是示例文件、环境变量指定了其他路径，或代理缓存了接口。 |
| API 返回空列表 | 开关、平台、时间窗口、版本范围；再看服务日志中的配置错误。 |
| API 有消息，App 不弹 | 是否新版 APK、实际服务器地址是否相同、是否已读同一 `id + revision`、是否回到首页前台。 |
| 文件无法读取 | 服务账号对 JSON 与父目录是否有读取／遍历权限。 |

日志命令：`sudo journalctl -u stu-assistant -n 50 --no-pager`。全部字段和边界见同目录的 [首页消息配置](首页消息配置.md)。
