# 按键触感

Android 的「我的 → 触感反馈」仅提供一个 0–100 强度滑条，默认 100，0 为关闭。拖动时以当前强度播放短反馈，最短 60 ms 一次，不排队、不在松手后补播。选择保存在本机。

默认按键使用两次独立的短促脉冲：按下时强度 100、相对锐度 52；点击确认时强度 100、相对锐度 100。滑条按比例缩放两段强度，锐度不变。快速点击的两段起点至少相隔 110 ms；长按后确认时立即发第二段。取消、滚动、失去焦点和进入后台会清掉待播放事件。

不包含调试台、引擎选择、跟随系统开关、曲线、包络或诊断导出。旧测试台的参数不再读取；旧版明确关闭触感的选择迁移为 0。网页不播放震动，也不展示这个 Android 设置。

## 原生实现

- 全局捕获按钮与链接的真实指针、键盘事件，覆盖图标内点击和弹层中的控件；禁用、已选中的分段、程序触发的点击不额外震动。原生复选框、下拉框以及分段控件的方向键采用单次选择反馈。
- 支持 RichTap 时使用同一份 HE 1.0 transient 参数，优先采用厂商公开扩展生成 `VibrationEffect`，其次采用 Lite SDK。Android 13 以上直连使用 `USAGE_PHYSICAL_EMULATION`，由 App 强度控制；不请求特权忽略标志。
- 不支持 RichTap 时自动选择设备支持的短原语、短幅度脉冲或系统预设。只支持预设的设备无法连续调节力度，但 0 仍完全关闭。系统也可能限制某些回退路径。
- 不使用自定义包络，不将提交成功当作马达实际输出的证明。SDK 为官方未修改的离线 Lite AAR，来源、固定提交和 SHA-256 见 `web/android/app/libs/README.md`，许可随 APK 打包。

## 验证与本机构建

```powershell
cd web
npm ci
npm run typecheck
# 一个终端启动页面，另一个运行真实浏览器输入检查
npm run dev -- --port 5187 --strictPort
node scripts/check-haptics.mjs
# 本机需 JDK 21、Android SDK 36，JAVA_HOME / ANDROID_HOME 可设在用户环境变量
./scripts/build-haptics.ps1
```

浏览器检查使用模拟的 Capacitor 边界，覆盖单滑条、默认值、持久化、关闭、取消手势、键盘重复、禁用按钮、插件失败和拖动限频。Java 单元测试验证固定 transient 编码、0–100 缩放和 110 ms 调度。

本机构建产出完整 App：包名 `com.stuassistant.app.haptics`、本机 Android debug key 签名、非 debuggable，能覆盖同一台构建机签名的前几版触感测试包，并与维护者正式发布的 App 并存。输出位于被 Git 忽略的 `release/`。可加 `-Server https://你的域名` 固定后端；不传时沿用 App 已存地址或首次登录填写。维护者正式版继续通过原有 release 构建与签名流程发布。

APK、签名文件、构建目录和测试截图不进入 PR；仓库只保留功能源码、必要的第三方依赖与许可、验证脚本和本文档。
