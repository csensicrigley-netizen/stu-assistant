# 原生登录、卡片与抽屉修复（1.0.51）

## 正式后台属于部署配置

正式地址为 `https://stu.oyishi.asia`。已在用户留存的旧正式 `stu-assistant.apk` 中核对：`assets/public/assets/index-jZyt71Gj.js` 的 API build base 是该地址；本轮匿名 `GET /v1/health` 返回 HTTP 200、`ok: true`，版本接口返回 1.0.35 / 36。这是助手账号与数据同步后台，不是学校教务地址。

原生应用使用 `assets/native-config.json` 的 `server`，登录、注册页删除服务器输入框、“连接到”和“更改”。网络或服务故障显示“服务暂时不可用，请检查网络后重试”，保留输入并允许用户重试；错误账号密码仍显示对应原因，不自动重复注册或登录 POST。

同一后台的原加密账号、校园凭据、课表缓存和本地设置沿用原 key。历史地址不一致时保留旧命名空间与加密恢复记录，不能将它的 token 发给新地址。旧 Web 正式包的地址可能仅在构建常量里，未写入 `stu.api`，因此迁移时需使用已确认的旧构建地址 `legacyServer`，不能随未来部署地址变化猜测身份归属。现有原生登录优先于残留 Web 登录。

自建部署者可以在自己的构建中配置 `server`；`legacyServer` 只描述其旧 Web 包的已知构建地址。两者都不进入学生端界面。不得把新部署地址直接当作旧 token 的归属。

## 首页卡片与抽屉

- 首页课程大卡、连接入口、有链接通知和可点课程行使用 Navigation 两段反馈，原强度 1.0；主底栏仍为单次 0.8。静态卡片不加触感。
- 可点卡片按压缩到 0.985 并出现轻微同色高亮。快速点按保留 80ms 的视觉状态，随后回弹；不额外补一轮震动。减少动态时只保留高亮。
- 抽屉按自身高度从底部滑入、滑出，沿用原 JS 的 SHEET 弹簧参数换算（单位质量 stiffness 400、damping ratio 0.8333）；蒙层 200ms 淡入淡出。
- AnimatedVisibility 统一拥有面板与蒙层动画；退出结束后才释放视觉层、背景触摸和焦点。返回、蒙层、关闭按钮、拖拽共用一次关闭逻辑，避免重复回调或点击穿透；堆叠抽屉关闭后恢复底层焦点，父层撤销时清理其子层。
- 系统减少动态时直接到最终状态。玻璃继续取同窗口 Compose backdrop，不增加截图桥接。

## 1.0.52：抽屉期间底栏常驻

底栏的显示条件不再依赖抽屉栈；使用同一个 Compose 实例保留原位置和选中状态。抽屉宿主为现有底栏容器预留 `104dp + 系统导航安全区`，从剩余高度计算面板最大高度；面板与蒙层均不遮住底栏，底栏绘制在它们上方。无底栏时沿用原安全区逻辑，避免重复计算。

底栏继续采样原 page/base backdrop，抽屉不进入它的采样源。模态期间底栏仍受焦点、语义和触摸保护，避免误切页；这与是否绘制底栏分开处理。

## 分支、版本、交付

已同步主线 `c13a7f9` 的 1.0.50 / 51 与版本防降级检查；本次接续为 1.0.51 / 52。

1. 每个独立任务用独立分支；并行会话使用独立工作目录。
2. 先提交任务改动，再 `git fetch origin`、`git merge origin/main`。逐处处理冲突，保留协作者修复。
3. `git merge-base --is-ancestor origin/main HEAD` 通过后还要审查最终差异，尤其账号、后台与版本文件。
4. 编译、单元测试、设备回归验证最终合并结果；登录、原生/旧 Web 数据恢复和覆盖升级分别记录证据。
5. 通过 PR 合并 main。Actions 在 PR 和 main 上执行版本检查、编译、单元测试与 lint，不上传 APK。
6. 版本数字以 Android `app/build.gradle` 为源，修改后运行 `python deploy/sync-version.py --write` 生成网页与后台数字，默认不带 `--write` 只检查。更新说明仍需人工准确撰写。
7. 交付脚本只接受已提交的干净源码。Gradle `preBuild` 强制验证非空 HTTPS 地址与三处版本一致；直接 IDE 构建也不能绕过。
8. `deploy/make-native-release.ps1` 打包后核验实际资产，记录源码 SHA、版本、APK SHA-256、配置 SHA-256 与目标后台。APK 和本地记录留在忽略的 `release/`，只提交源码。

Haptics 测试包仍使用原 `.haptics` 包名与本机构建签名，可以覆盖原测试版本；正式 `.app` 发布需要维护者原签名。健康接口成功不等于真实学校账号登录已验收，模拟器不能验证实际马达手感。
