# 首页消息弹窗

首页消息用于开发者来信、活动海报和临时公告。用户进入「今天」时从 App 当前连接的 API 服务器读取配置，一次打开最多展示一条；默认附带官方 GitHub 仓库的求 Star 消息。Android 使用现有 Liquid Glass 组件，网页版使用同色系玻璃弹窗。关闭不影响正常使用。

服务器由另一位仓库作者维护时，直接交付 [服务器维护者操作手册](首页消息-服务器维护者操作手册.md)。首次需要维护者部署新后端、用户更新支持此功能的客户端；后续内容修改只改服务器 JSON。

这是应用内消息：用户打开首页时读取，不要求通知权限，不会在 App 关闭后发送系统通知。

弹窗覆盖在「今天」的真实内容上，页面和底部导航保留为玻璃背景；展示期间暂停背景交互，关闭后恢复。默认文案同时邀请 Star、Issue 和 PR。无配图时使用已发布的真理钟图标，随 App 的浅深主题切换；卡片 36 dp 圆角、20 dp 内边距、按钮 16 dp 圆角使用同一套内嵌轮廓。

Android 启动背景也读取已保存的主题与色系，并同步进入首页时的窗口底色。Android 12 及以上使用系统持久化启动主题，让下一次冷启动直接使用对应颜色；更早系统在进程创建后应用设置，进程创建前的系统预览仍受系统限制。

## 配置一次，之后直接改 JSON

默认配置位置是 `$STU_APP_HOME/announcements.json`。标准安装对应 `/var/lib/stu-assistant/announcements.json`，不在每次更新会覆盖的程序目录内。

```bash
# 第一次配置：复制内置的 GitHub 求 Star 消息
sudo install -o stu-assistant -g stu-assistant -m 640 \
  /opt/stu-assistant/app/announcements.example.json \
  /var/lib/stu-assistant/announcements.json
sudoedit /var/lib/stu-assistant/announcements.json
```

修改内容和图片链接后发布即可；**不用重启服务，不用重新打 APK**。客户端首次进入首页、从后台回到前台时读取新配置；当前已打开的卡片不会被替换，也不在前台持续轮询。已读用户需要重新收到时将 `revision` 加一。首次安装尚无默认配置文件时使用内置求 Star 消息；创建空列表或关闭总开关即可停用。

如果需要其他路径，在 `/etc/stu-assistant.env` 配置 `STU_APP_ANNOUNCEMENTS_FILE=/你的目录/announcements.json` 后重启服务一次。自定义路径不存在时停用弹窗，不回退到内置消息。

## 完整示例

```json
{
  "enabled": true,
  "announcements": [
    {
      "id": "github-star",
      "revision": 1,
      "enabled": true,
      "eyebrow": "开发者来信",
      "title": "给小助手一颗 Star",
      "body": "如果小助手帮到了你，欢迎来 GitHub 点亮一颗 Star。\n也欢迎提交 Issue 反馈问题、分享想法，或贡献 PR，一起让它变得更好。",
      "image_url": null,
      "image_alt": "",
      "action_label": "去 GitHub 点亮 Star",
      "action_url": "https://github.com/csensicrigley-netizen/stu-assistant",
      "effects": ["star-struck", "heart-on-fire", "folded-hands", "party-popper", "keycap-one-6"],
      "display": "once",
      "priority": 0,
      "platforms": ["android", "web"],
      "starts_at": null,
      "ends_at": null,
      "min_version_code": null,
      "max_version_code": null
    }
  ]
}
```

| 字段 | 作用 |
| --- | --- |
| `enabled` | 文件总开关和每条消息的独立开关，默认 `true`。 |
| `id` | 消息固定编号，用字母、数字、点、下划线、短横线；同一文件内不能重复。 |
| `revision` | 正整数版本，默认 `1`；需要看过的人重新收到时加一。 |
| `eyebrow` | 顶部短标识，默认「开发者来信」。 |
| `title` / `body` | 标题和纯文本正文；正文 `\n` 换行，不执行 HTML 或脚本。正文可留空。 |
| `image_url` / `image_alt` | 可选图片与描述。支持 HTTPS 地址或下文的服务器图片路径。 |
| `action_label` / `action_url` | 主按钮文字与 HTTPS 链接；链接设 `null` 时作为纯消息展示。 |
| `display` | `once`：此版本首次展示后不再展示；`daily`：每天最多一次；`always`：每次重新打开最多一次。默认 `once`。 |
| `effects` | 可选内置动画 ID 数组，每次弹窗从中随机选一个、只播放一次；省略或 `[]` 关闭。最多 5 个，不接受远程动画地址。 |
| `priority` | 数字越大越先展示；同优先级按配置顺序。默认 `0`。 |
| `platforms` | `android`、`web` 的子集，默认两端。 |
| `starts_at` / `ends_at` | 可选生效和失效时间，必须含时区，例如 `2026-11-20T08:00:00+08:00`。起点包含，终点不包含。 |
| `min_version_code` / `max_version_code` | 可选装机版本范围，包含边界；未上报版本的客户端不接收限制版本的消息。 |

消息首次展示时就记住本版本已读，不必点击主按钮。同一客户端会话最多出现一条，不连着弹多条；下次打开会从符合条件的消息中选择优先级最高且尚可展示的一条。记录按服务器与账号隔离，清除 App 数据或浏览器站点数据会清除本机记录。每日频次按北京时间日期计算。

Android 上点击 GitHub 链接优先唤起已安装的 GitHub App；未安装或无法处理时回退到浏览器。其他 HTTPS 链接由系统选择能够处理的应用。

## 放一张图片

可以直接填公开 HTTPS 图片地址，也可以把图片放到服务器。推荐比例接近 `16:9`、宽度约 `1200px`，保持文件轻量；文字内容同时放正文，避免仅靠海报传递信息。

```bash
sudo install -d -o stu-assistant -g stu-assistant -m 750 /var/lib/stu-assistant/announcements-assets
sudo install -o stu-assistant -g stu-assistant -m 640 ./welcome.webp \
  /var/lib/stu-assistant/announcements-assets/welcome.webp
```

把该条消息改为：

```json
"image_url": "/v1/announcements/assets/welcome.webp",
"image_alt": "欢迎使用 STU 事项助手"
```

图片目录固定在 `$STU_APP_HOME/announcements-assets`，与 JSON 是否改了路径无关。文件名使用字母数字开头及字母数字、点、下划线、短横线；支持 PNG、JPG、JPEG、WebP、GIF。不提供 SVG、目录浏览或上传接口。这里的图片和消息均为公开内容，不放隐私文件。

## 停用、校验与发布

立即停用所有新弹窗：

```json
{"enabled": false, "announcements": []}
```

也可以使用空数组 `[]`。只隐藏一条时，把那条的 `enabled` 改为 `false`。

正式替换前可先校验草稿，防止 JSON 语法错误或时间写错：

```bash
cd /opt/stu-assistant
venv/bin/python -m app.announcements --check /var/lib/stu-assistant/announcements.next.json
# 校验通过后原子替换；草稿与正式文件需位于同一目录
sudo mv /var/lib/stu-assistant/announcements.next.json /var/lib/stu-assistant/announcements.json
```

错误配置、重复编号、非法链接、无时区时间、超过 256 KiB 的文件会让本次请求返回空列表，服务日志提示「首页消息配置无效或无法读取，本次停用弹窗」；不会误显示旧消息或内置消息。最多配置 100 条，标题最多 120 字、正文最多 3000 字。JSON 允许 UTF-8 BOM。

API：无需登录的 `GET /v1/announcements?platform=android&version_code=59`，返回 `{"announcements":[...]}`。服务器过滤时间、版本、平台后排序；响应不缓存。没有登录令牌、校园信息或设备令牌参与消息配置。

## 弹窗出现时的动画

默认 GitHub 来信启用以下五款，在固定排版上叠加原始 Telegram 矢量动画。每次出现随机选一款，约 2.5–3 秒后自动移除；不会拦截按钮点击，也不循环播放。关闭弹窗、App 进入后台时结束；系统“减少动态效果”开启时跳过。

| 配置 ID | 用户选定的原始素材 |
| --- | --- |
| `star-struck` | U+1F929 · #0 |
| `heart-on-fire` | U+2764_U+200D_U+1F525 · #0 |
| `folded-hands` | U+1F64F · #0 |
| `party-popper` | U+1F389 · #0 |
| `keycap-one-6` | U+31_U+20E3 · #6 |

例如 `"effects": ["star-struck", "party-popper"]` 只从星星与礼花中随机选择；维护通知可写 `"effects": []`。旧配置不写该字段时保持静态。

Android 使用原生 Lottie Compose，Web 使用按需加载的 Lottie SVG 播放器。素材随客户端打包，播放时不访问 GitHub 或第三方站点。素材来自 [Telegram emoji effects](https://ilyhalight.github.io/telegram-emoji-effects/)，固定来源版本、原始文件哈希与上游权属说明记录在 [素材来源](third-party/announcement-effects.json)。更新选定素材可运行 `node web/scripts/import-announcement-effects.mjs`。

卡片采用 560ms 轻浮入场和 260ms 回落淡出，遮罩分别过渡；表情与卡片入场使用同一播放起点，不等待卡片落稳。素材加载期间不展示静止首帧，加载完成后直接跟上当前时间进度；若整段特效已结束则跳过，不补播。原生 Compose 使用显示帧时钟与高帧率偏好，以连续时间进度直接驱动 Lottie 矢量画面，避免按素材帧率量化或逐帧取整时间；网页播放器启用子帧插值并跟随浏览器帧时钟。120／144Hz 下可以产生更多中间帧，动画时长不变；实际帧率由设备、系统节能策略、浏览器和渲染负载决定。减少动态效果时去掉位移缩放和表情，仅保留短淡入淡出；系统完全禁用动画时遵循系统设置。
