# 事项 V1：构建、验收与交付

本文对应[事项升级 V1](事项升级V1.md)。产品功能终点为 `cc59496`（1.1.3 / 59）；后续整理仅清理未引用的旧 UI 和冗余代码，并归并文档。历史验证和整理后的源码检查分别登记，不把旧测试结果写成刚刚全套重跑。

## 1. 环境和入口

| 工具 | 当前源码要求 |
| --- | --- |
| Java | JDK 21 |
| Android | minSdk 24、compileSdk 37、targetSdk 36；CI 安装 `platforms;android-37.0` 与 `build-tools;36.0.0` |
| Gradle | 使用仓库 `web/android/gradlew` wrapper，不依赖全局 Gradle |
| Node | CI 使用 Node 22，安装 `web/package-lock.json` 锁定依赖 |
| Python | 项目后端开发使用 Python 3.12；版本脚本只需其标准库 |
| 设备 | 本轮设备证据来自 API 37 模拟器；真机体验单独记录 |

源码入口是 `web/android`，当前 Android 页面由 Compose 提供。既有 Capacitor 模块仍是构建依赖，不代表本机原生交付包继续运行网页 UI。

首次检出先安装 `web` 依赖，并按 [.github/workflows/android.yml](../.github/workflows/android.yml) 准备 Capacitor Android 依赖。CI 的 `dist-android/index.html` 是构建占位文件，不是产品页面；本机交付脚本会核验 APK 没有夹带网页业务 bundle。已有配置的开发目录不要用占位文件覆盖其真实网页产物。

Android SDK 路径使用本机 `local.properties` 或环境变量。Windows 若 Android 工具不适应中文路径，可把**已有检出**映射到空闲 ASCII 盘符；只在本机使用，不把绝对机器路径提交仓库。

## 2. 不联网的源码检查

在仓库根目录：

```powershell
python deploy/sync-version.py
python -m unittest discover -s deploy/tests -p test_version_policy.py
```

在 `web/android`：

```powershell
./gradlew.bat --console=plain --max-workers=2 `
  :app:assembleDebug :app:assembleDebugAndroidTest `
  :app:testDebugUnitTest :app:lintDebug
```

依赖已缓存时可加 `--offline`；首次环境缺依赖时按正常 Gradle 下载流程准备。Linux/macOS 使用 `./gradlew` 和对应环境变量，不复制 PowerShell 续行符。

这些命令不运行设备测试，也不会调用 Jev。当前 JVM 套件 56 项，版本策略套件 14 项；数量随之后提交变化，判断以该提交的实际报告为准。

## 3. 离线设备回归

先用 `adb devices` 确认目标，下面示例使用 `emulator-5554`，需要时替换。执行测试前停止同一模拟器上的其他自动化；不要在 instrumentation 期间另起 `uiautomator dump` 抢占其 UiAutomation 会话。

在 `web/android` 安装两个调试包：

```powershell
$device = 'emulator-5554'
adb -s $device install -r app/build/outputs/apk/debug/app-debug.apk
adb -s $device install -r app/build/outputs/apk/androidTest/debug/app-debug-androidTest.apk
```

设备回归的关键测试类：

| 类 | 验证内容 |
| --- | --- |
| `NativeItemsInteractionInstrumentedTest` | 详情与完成命中分离；完成行保留、可撤销；学业页面和逐级返回；往返保留详情 |
| `NativeSoftEdgeInstrumentedTest` | 真实 GPU 模糊降低顶部条纹对比，正文和底部像素不变 |
| `NativeCardSheetMotionInstrumentedTest` | 八项共用卡片/抽屉回归，覆盖焦点、返回、嵌套、退出拦截、取消和降低动态 |
| `NativeCalendarCounterInstrumentedTest` | 快速更新逐帧有字、位数增长可见、停止后清晰、降低动态模式 |
| `NativeCalendarOnlineTest#compactTimeEditorKeepsAllFieldsUsable` | 不联网的同屏日期/开始/结束编辑及软件键盘 |
| `NativeCalendarOnlineTest#threeDayDragAndBothResizeHandlesKeepTheirMeaning` | 不联网的跨列改日期及上下抓手语义 |
| `NativeStoreInstrumentedTest` | 存储、账号及迁移回归，包含新日历批次持久化检查 |

例如单独运行事项交互：

```powershell
adb -s $device shell am instrument -w `
  -e class com.stuassistant.app.nativeapp.NativeItemsInteractionInstrumentedTest `
  com.stuassistant.app.gpuqa.test/androidx.test.runner.AndroidJUnitRunner
```

其他类使用相同 runner 替换 `-e class`。测试 UI 使用本机合成数据和独立回调；截图只作为本机证据。布局验证应包含默认尺寸与窄屏、软件键盘、长中文、展开中间帧；改动模拟器尺寸/密度/键盘设置后恢复原值。不要以卸载或清用户数据解决回归失败。

## 4. 显式启用的真实在线验收

`NativeCalendarOnlineTest` 中两个真实网络方法默认跳过，必须显式提供 `calendarOnline=true`。它们注册临时 STU 测试账号，使用隔离偏好/目录，结束删除测试账号；失败或进程中断时依测试恢复逻辑清理。

```powershell
adb -s $device shell am instrument -w `
  -e class com.stuassistant.app.nativeapp.NativeCalendarOnlineTest#realJevKeyboardDragAndEncryptedPersistence `
  -e calendarOnline true `
  com.stuassistant.app.gpuqa.test/androidx.test.runner.AndroidJUnitRunner
```

另一个方法为 `realDeadlinePointDrag`。它们使用真实 `https://stu.oyishi.asia` 身份和 `https://stu-mcp.com/api/calendar/v2/mobile/parse`，会消耗真实 Jev 用量。普通构建、Lint、离线设备类不应自动开启该开关。

线上测试不需要在 APK 中放 Jev Key，也不应在聊天、代码、环境示例或报告中复制真实 Key。错误不得被模板结果替代；对 POST 不自动重发。课程动态分类不属于这些手动新建验收。

## 6. 构建与交付规则

1. 产品版本的唯一源是 `web/android/app/build.gradle` 的 `defaultConfig`，同步使用 `python deploy/sync-version.py --write`。探针登记独立，不能用其数字推高产品功能版本。
2. 先提交源码，再同步主线并验证最终结果。交付脚本拒绝脏工作树；临时开发包可以直接 Gradle 构建，但不冒充可追溯交付包。
3. 同包名 versionCode 必须高于已经交付的版本。`deploy/probe-versions.json` 的 `lastDeliveredVersionCodes.com.stuassistant.app.haptics` 已依据 1.1.3 的真实回执补到 `59`，其他包的下限不变。
4. 本次整理沿用 1.1.3，仅提交代码/文档，没有重新生成同版本交付包。今后若要发新包，先提高该产品的 versionCode；不能改写旧回执或删除下限来绕过检查。
5. 完整 App 本机验证使用：

```powershell
./deploy/make-native-release.ps1 -Variant Haptics
```

该命令是今后交付流程，不是让当前 `59` 重发一次。依赖缺失时先准备环境；正式 Release 还需要维护者的受保护签名配置。不要把签名材料放入仓库。

6. 脚本生成本机 `release/` APK 和 `.apk.json` 回执，检查版本、包名、内置 HTTPS 后台、源码 SHA、配置 SHA 和 APK 散列，确认未夹带网页 bundle。签名与上一版相同，才能按既有包名覆盖更新。
7. 产品 PR 通过后合入 main；检查回执源码在 main 历史内，并核对交付树与预期源码。APK、签名及设备数据不进 GitHub。正式网页下载、生产部署和产品 Release 需要独立的真实发布验收，不能由一个版本常量或 Milestone 推断。

完整版本制度和历史探针记录见[版本与验证构建](版本与验证构建.md)。

## 7. 升级与回退

新日历数据使用独立的 `calendar-v1:` 账号命名空间。旧云计划继续原有接口，不进行静默删除或大规模迁移。更新使用同包名、同签名且更高 code 的覆盖安装，保留本地加密空间。

需要回退行为时，从已知源码恢复并以更高 code 构建兼容修复版，通过隔离数据回归后交付；不要直接把低版本 APK 当作可覆盖回滚包。旧版 Store 未必知道新命名空间的保留规则，不能直接恢复旧 Store 后让用户执行登出/清缓存。卸载、清数据也不是回退步骤；不得在没有兼容方案时牺牲用户本地事项。

## 8. 手动验收清单

- [ ] 新建入口唯一，键盘自动唤起；新增不顶走原列表。
- [ ] 固定“建议”与“确认”；加载、失败、结果、返回无生硬切换。
- [ ] 三列共用时间轴；单指平移、双指缩放及切日相互独立。
- [ ] 点/段/DDL 语义正确；移动保留时长，上下抓手只改其负责端点。
- [ ] 同屏时间编辑在窄屏和键盘下仍可操作；结束为空保持时间点。
- [ ] 标题/箭头不触发完成；完成行不消失，可取消；来源链接可打开。
- [ ] 学业子页标题与返回一致；列表和账号上下文正确。
- [ ] 顶部柔化和日历上下材质无硬盖板、背景穿透或点击遮挡。
- [ ] 新事项仅本地保存，重复确认不重复，账号切换拒绝旧确认。
- [ ] 提醒未被当作已调度，课程动态未被当作已完成 Jev 分类。

清单用于今后每次验收，不表示本次对每一种机型和系统组合都已打勾。实际结果应注明源码、设备、构建和范围。
