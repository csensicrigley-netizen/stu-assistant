## 1. 充电桩（已可跑）

### 1.1 平台基本信息

| 项 | 值 |
|---|---|
| Base | `https://wx.isfdz.com` |
| 协议 | HTTPS，不跟随跳转，不用系统代理 |
| 鉴权 | **无需登录**，但要 `app_id` + `app_secret` 签名 |
| 配置有效期 | 6 小时（`CONFIG_TTL_SECONDS = 21600`） |
| 单轮上限 | 18 次请求 / 40 秒 |

### 1.2 签名机制（三步）

**第一步：发现客户端脚本**

```http
GET https://wx.isfdz.com/
```

从 HTML 里找 `<script src="/static/js/index.<hash>.js">`，路径必须匹配：

```
/static/js/index\.[a-f0-9]{6,64}\.js
```

候选必须**唯一**，否则视为平台改版。

**第二步：从脚本里提出两个字符串**

在脚本里找形如 `{app_id: "…", app_secret: "…"}` 的**字面量对象**（键名固定，值必须是纯字符串、无转义）。两个值都只能出现一次。

**第三步：签名**

```python
values = {**params, "timestamp": int(time.time()), "app_id": app_id}
basis  = "".join(f"{k}={values[k]}" for k in sorted(values)) + app_secret
sign   = hashlib.md5(basis.encode("utf-8")).hexdigest()
```

- 键按**字典序**拼接，`k=v` 用 `=` 连、条目之间**无分隔符**
- 末尾**直接拼** `app_secret`
- `timestamp` 是 Unix 秒（整数），不是 ISO 字符串
- GET 走 query，POST 走 JSON body，两者签的内容一样

**签名失效怎么办**：平台返回 `{code, msg}` 且 `msg` 为 `签名错误` 或 `时间戳已过期` → 重新拉一次脚本、重新提取 `app_secret`、再签一次。连续两次失败才算真失败。

### 1.3 两个业务接口

**① 查设备类型**

```http
GET /api/charge/mobile/getEquipType?code=<设备编号>
```

返回整数 `kind`，决定下一步走哪个协议：

| 协议 | 适用的 kind |
|---|---|
| `afterProtocol` | 2, 6, 8, 10, 11, 12, 13, 14 |
| `beforeProtocol` | 1, 3, 4, 5, 7, 9 |

**② 查插座状态**

```http
POST /api/equi/afterProtocol/getLineInfo
Content-Type: application/json
```

```json
{"code": "4GR00008477", "parentCode": ""}
```

（`beforeProtocol` 同理，路径换掉即可。）

### 1.4 响应与状态码

统一信封：

```json
{"code": 200, "data": [...]}
```

| `code` / `msg` | 含义 | 处理 |
|---|---|---|
| `200` | 成功，取 `data` | 解析插座 |
| `401` / `403` | 平台拒绝公开读取 | 报 `access_denied` |
| `429` | 限频 | 报 `rate_limited`，按 `Retry-After` 退避 |
| `msg` 含 `设备不在线` | 设备离线 | 报 `device_offline`，**不要**当成 0 空闲 |
| `msg` 为 `签名错误` / `时间戳已过期` | 配置过期 | 重拉配置重签 |
| 其他非 200 | 业务失败 | 报 `source_error` |

插座状态表：

| state | 含义 | 计入 |
|---|---|---|
| 0 | 粘连故障 | 异常 |
| 1 | 空闲 | **空闲** |
| 2 | 占用 | 占用 |
| 3 | 开路故障 | 异常 |
| 4 | 设备急停 | 异常 |
| 5 | 过温保护 | 异常 |
| 6 | 烟感报警 | 异常 |
| 7 | 过压故障 | 异常 |
| 8 | 欠压故障 | 异常 |

`data` 是数组，每项 `{"num": int, "state": int}`。校验要点：`num` 在 `1..capacity` 且不重复，`state` 是非负整数；任一项不合格 → 整批作废（结构变了），**不要**保留上次数据。

## 2. 公交实时到站

### 2.1 现状与契约

数据源是**车来了**（`chelaile`）。它的站点接口需要三个值：

| 配置 | 环境变量 | 说明 |
|---|---|---|
| 城市 ID | `STU_TRANSIT_CITY_ID` | 汕头市的 `cityId` |
| 签名密钥 | `STU_TRANSIT_SIGN_KEY` | 客户端内置的 key |
| 用户标识 | `STU_TRANSIT_USER_ID` | 可空，部分接口要求 |

以及**每个站点自己的 `stopId`**，写在 `backend/app/transit.py` 的 `STOPS[*]["external"]` 里，现在都是 `[填写车来了 stopId]`。

开关：

```bash
STU_TRANSIT_PROVIDER=chelaile    # 不设或设 demo 就用演示数据
```

### 2.2 请求形状（当前实现）

```http
GET {base}/bus/stop?cityId=…&stopId=…&cne=true&v=3.1.0&src=3&userId=…&sign=…
```

签名：

```python
ordered = "&".join(f"{k}={params[k]}" for k in sorted(params))
params["sign"] = md5((ordered + sign_key).encode()).hexdigest()
```

解析：`data.lines[]` → 每条线路取 `buses[]`，`time` 就是「还有几分钟」，负数或非数字跳过。

> 这套签名与查询参数是照通用实现写的，**接真机时以车来了当前版本的抓包为准**；只有 `sign` 的拼法与参数名可能变，返回结构（`data.lines[].buses[].time`）历来稳定。

| `sp-gate` | 桑浦山 | 汕头大学东门 | 5路 / 12路 | `[待填]` |

### 2.4 我方接口

```http
GET /v1/transit                    # 校区 → 站点树 + 当前 provider
GET /v1/transit/<stop_id>          # 该站全部线路的到站时间
```

```json
{
  "stop": {"id": "sp-main", "name": "汕头大学", "campus": "桑浦山"},
  "provider": "chelaile",
  "generated_at": 1730100000,
  "arrivals": [
    {"line": "2路", "minutes": 3, "eta_at": 1730100180, "vehicle": "1234", "crowded": false}
  ]
}
```

前端拿到 `eta_at` 后**本地倒计时**，不等下一次轮询：列表 30 秒拉一次，界面每 15 秒重算一次显示。

### 2.5 演示数据规则（`demo` provider）

按 `(站点, 线路, 30 秒时间桶)` 做哈希，得到 1–14 分钟的底数，同一线路再给第二班（+8~16 分钟）。所以它稳定、可复现、看着像真的，但**不是真的**。

## 4. 配置清单

### 4.1 后端环境变量

```bash
# 数据目录（多租户隔离，每个 uid 一个子目录）
STU_APP_HOME=/data/stu-app

# 演示模式：不碰真实校园系统
STU_APP_DEMO=1

# 公交
STU_TRANSIT_PROVIDER=chelaile        # demo | chelaile
STU_TRANSIT_CITY_ID=[待填]
STU_TRANSIT_SIGN_KEY=[待填]
STU_TRANSIT_USER_ID=[可空]

# 同步与限流
STU_SYNC_MIN_INTERVAL=600             # 同一用户两次同步最小间隔（秒）
STU_LOGIN_MAX_PER_HOUR=3              # 每小时最多登录尝试
```

### 4.2 目录权限

```
$STU_APP_HOME/<uid>/        0700
$STU_APP_HOME/<uid>/key     0600    Fernet 主密钥
$STU_APP_HOME/<uid>/vault/  0700    加密后的 Cookie
```

### 4.3 每租户隔离

`stu-mcp` 靠两个环境变量定位自己的库：

```python
STU_MCP_HOME      = f"{STU_APP_HOME}/{uid}"
STU_MCP_KEY_FILE  = f"{STU_APP_HOME}/{uid}/key"
```

`tenant_scope(uid)` 上下文管理器负责设置 + 加锁，退出即还原。

## 5. 联调步骤

### 5.1 充电桩

```bash
# 1. 装依赖
cd backend && pip install -r requirements.txt

# 2. 起服务
uvicorn app.main:app --host 127.0.0.1 --port 8100

# 3. 探活
curl -s localhost:8100/v1/charging/devices | jq '.live, (.devices|length)'
# 期望 live=true, 14

# 4. 拿一台的状态
curl -s localhost:8100/v1/charging/4GR00008491 | jq '.state.counts'
# 期望 {total:20, observed:20, free:N, occupied:M, fault:0, unknown:0}
```

### 5.2 公交

```bash
# 先确认 demo 通路
curl -s localhost:8100/v1/transit | jq '.provider, (.campuses[0].stops|length)'

# 切真实前先填三项配置，再
export STU_TRANSIT_PROVIDER=chelaile
curl -s localhost:8100/v1/transit/sp-main | jq '.provider, (.arrivals|length)'
```

### 5.3 校园系统（首次绑定）

```bash
# 绑校园账号（密码只用一次，不落盘）
curl -s -X POST localhost:8100/v1/bind \
  -H 'Authorization: Bearer <token>' \
  -H 'Content-Type: application/json' \
  -d '{"student_id":"[学号]","password":"[密码]"}'

# 轮询绑定任务，可能要求验证码/短信
curl -s localhost:8100/v1/bind/<job_id> | jq '.state, .challenges'
curl -s -X POST localhost:8100/v1/bind/<job_id>/input \
  -H 'Content-Type: application/json' -d '{"challenge_id":"…","value":"…"}'

# 绑定成功后拉一次
curl -s -X POST localhost:8100/v1/sync -H 'Authorization: Bearer <token>' | jq '.report'
```

退出码沿用 B 机那套：

| code | 含义 | 前端表现 |
|---|---|---|
| 0 | 正常 | 静默 |
| 1 | 失败 | 消息页提示 |
| 2 | 维护中 | 「我的」里写维护中，不告警 |
| 3 | 需重新登录 | 引导重新绑定 |
| 4 | 密钥库异常 | 提示重启应用 |

## 6. 工程约束

1. **不存密码**：绑定用一次即丢，库里只有加密 Cookie。
2. **不并发登录**：同一租户一把锁，避免踢掉自己的会话。
3. **限速**：充电 18 次/40 秒；树洞 40 次/45 秒；同步间隔 ≥10 分钟。
4. **结构变更即失败**：字段/表头/选择器对不上时宁可报错，也不要把「解析失败」当成「没有数据」。
5. **HTTP 目标只放行白名单**：`charging` 只允许 `/`、`/static/js/index.<hash>.js`、三个 `/api/` 路径；越界直接拒绝。
6. **不跟随跳转**：所有校园请求 `follow_redirects=False`，避免被引到钓鱼页。
