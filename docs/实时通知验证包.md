# 实时通知验证包

本验证用于确认个人开发者侧载 APK 能否通过 Android 公开 Live Updates 通知能力显示系统胶囊。现已收到一台 ColorOS 17 真机的成功反馈，下一站是 vivo／iQOO OriginOS。OPPO、小米、vivo、华为专有 SDK 与白名单接口不包含在此验证中。

## 已有结果与边界

2026-10-31，用户提供反馈及 4 张截图：设备为 **OPPO PKC110，Android 17／API 37，系统构建 `PKC110_17.0.0.103(CN01)`**。诊断中的 `eligible`、`allowed`、`active`、`promoted` 均为 `true`；截图显示系统流体云展开进度卡片、通知栏通知，以及显示 `02:49` 的状态胶囊。

该机需要在本应用的系统通知设置中开启 **「流体云显示实时活动」**。入口为验证页「实时通知 / 提升设置」→ 本应用系统通知设置 →「流体云显示实时活动」；不同系统的入口和开关名称可能不同。

以上是**用户真机反馈与截图证据，不是维护者持机测试**。仅确认该型号、该构建下公开 API 路线成功呈现系统流体云；不外推所有 ColorOS 设备，也未验证锁屏、进度到 100%、自动过期或倒计时全程连续变化。

## 安装与下一轮 vivo／iQOO 测试

独立包名 `com.stuassistant.app.liveprobe`，桌面名称「STU 实时通知验证」，与原 App 共存。无需登录，不读原 App 数据。该变体移除网络、前台服务与振动权限，不申请悬浮窗、通知读取或辅助功能。

现有 **`1.0.55-liveprobe.1` APK 可直接复用**，无需为下一品牌另打包。仍验证公开 API，不代表 vivo 私有原子通知 SDK、场景审核或白名单已经接入。

当前包仅在 **Android 16／API 36 及以上**尝试标准提升通知；更低 API 只发普通通知，不能据此否定厂商私有岛能力。OriginOS 名称不能代替 Android/API 版本，应以诊断为准。已公开的作者实测覆盖一台海外 V60 Lite／OriginOS 6：进度可入岛，但倒计时胶囊可能显示应用名。因此两种模式要分别记录结果，不把「时钟没动」直接算作整体接入失败。

1. 安装并打开验证包，记录手机型号、完整 OriginOS 版本／构建号，以及页面的 Android 版本和 API；不要只写「vivo」或「最新系统」。
2. 允许通知，查看「应用通知设置」与「实时通知 / 提升设置」。如有相关开关则开启并记下名称；没有时如实记录，不使用强制授权。
3. 点「进度测试」，回桌面查看顶部胶囊和通知栏，截图记录；回 App 点「推进进度」，再观察内容是否更新。到 100% 的结果单独记录。
4. 结束进度测试，再点「3 分钟倒计时」，回桌面观察胶囊文字是否随时间变化。App 内倒计时在走，不能代替胶囊内计时证据。
5. 分别记录前台、桌面／其他应用和锁屏表现；未测试的场景写「未测」，不要用通知栏截图代替锁屏证据。
6. 用「结束测试」或通知中的结束动作检查通知收回；另一次测试可划除通知，观察是否保持结束、不自动补发。自动过期未完整等待时标为「未测」。
7. 返回 App 刷新并「复制诊断」，连同上述机型／构建、实际视觉表现和截图反馈。`allowed`、`eligible`、`active`、`promoted` 与肉眼观察分别记录；诊断不含账号或课表。

每次开始都由用户明确触发，仅替换本验证包自己的同一条通知。进度每次更新 20%；倒计时更新不重置结束时间。API 26 起，进度通知十分钟自动过期，倒计时在结束约一秒后过期；API 24/25 需手动结束。无服务或后台截图采样。

## 如何判断结果

| 检测 | 能说明什么 |
| --- | --- |
| 通知权限与渠道 | 系统是否允许此 App 发普通通知 |
| `canPostPromotedNotifications()` | 系统的应用级提升通知开关 |
| `hasPromotableCharacteristics()` | 通知构造是否符合提升格式条件；缺少该 API 时显示未知 |
| 活跃通知 | 系统是否接收并保留通知 |
| `FLAG_PROMOTED_ONGOING` | 系统实际赋予的提升标志；应用不自行设置 |
| 真机视觉观察 | ColorOS 等厂商 ROM 是否呈现胶囊、动画和倒计时 |

通知发送成功、格式符合或提升开关开启，均不能单独证明厂商胶囊成功。某些 ROM 可能显示胶囊但不暴露标准提升标志；应同时记录检测和视觉结果。AOSP 模拟器验证不能代替 ColorOS 17 验收。

## 源码与构建

实现位于 `web/android/app/src/main/java/com/stuassistant/app/liveprobe/`。原 App 的启动页保持不变；`src/liveprobe/AndroidManifest.xml` 只在验证变体把验证页设为独立启动入口。Android 16 以下保持普通通知；Android 16 的次版本 API 差异受保护，公开 request extra 可用于缺少便捷方法的版本。API 36 仅在系统自己判定新格式不符合、旧 colorized 格式符合时使用旧格式，并在诊断中记录；API 37 起遵循当前非 colorized 格式。

```powershell
# 开发验证
./web/android/gradlew.bat -p web/android :app:assembleLiveprobe
# 干净且已提交的源码交付；生成本地 APK 与源码/版本/SHA256 收据
./deploy/make-native-release.ps1 -Variant Liveprobe
```

APK、签名材料及诊断不上传 GitHub，仅提交源码和测试。发布真实课程通知前，仍需验证提醒触发、通知寿命和用户主动进行中的场景，不能把这个手动探针当作已完成的课程接入。
