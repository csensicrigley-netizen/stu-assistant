# Compose 原生重写 V1：范围与实施顺序

日期：2026-10-30。本文以用户最新收敛为准：**首版只做五导航合并，其余页面按现有 JS 功能等价移植为原生 Compose。** 不把此前提出的全局信息架构、密度和页面布局重设计混入首版。

用户已确认，“合并计划和列表栏”指合并个人计划与学校作业列表。当前 Android `1.0.31-gpu.1` 仍是六导航的 WebView/GPU 底栏验证包；本文是下一版的实施基准，不代表原生业务页面已经完成。

## 1. 首版固定的五个入口

| 入口 | 对应现有功能 | V1 允许的变化 |
| --- | --- | --- |
| 今天 | 当前/下一节课、当天课程与空档、临近作业、校历节点、新通知 | 按原页面结构与字段迁移；原“全部作业”跳转事项中的作业筛选。 |
| 课表 | 换周、选日、课程分布、当天列表、课程详情、未排定课程、来源与导入入口 | 保留既有功能与主要操作；不把考试、成绩搬入此页。 |
| 事项 | 原计划与原学业合并后的目的地 | 待办合并个人计划与学校作业；保留考试、成绩两个子视图。 |
| 校园 | 通知、生活、校历 | 保留原分组和主要功能；不在 V1 重排整个首页、移除栏目或另造服务仪表。 |
| 我的 | 账号与来源、同步/重连、外观、触感、更新、反馈、隐私、退出/删除 | 按原页面能力迁移；不将其变成学业记录的新入口。 |

旧代码对应：`web/src/components/TabBar.tsx`、`web/src/screens/`。逐项能力与验收依据见 [Compose 首版功能对照表](Compose首版功能对照表.md)。

此前讨论的“日程/学业/校园三导航”“五导航但第二项改名学业”“考试归课表、成绩归我的”等方案均不进入 V1。旧文档中的相关建议保留为研究历史，不再作为当前实施要求。

## 2. 合并事项的最小改动

事项保留原学业的三个显式子视图：**待办 / 考试 / 成绩**。考试与成绩的字段、学期筛选、原文时间、估算口径及展示层次沿用现有实现，不另设新的顶层入口。

待办提供 **全部 / 个人 / 作业** 的来源筛选：

- 全部：在同一清单展示个人计划与学校作业，条目保留清楚的短来源与时间语义。日期分组内可混排，不复制同一条记录。
- 个人：保留原计划页的日期选择、日统计、时间/备注/优先级、新建、完成/撤销、排序和删除。
- 作业：保留原作业页的截止分组、课程/来源、学校状态、本机勾选、已完成折叠和原站入口。

“新建计划”明确创建个人数据；不提供新建学校作业或提交学校作业。排序继续限制在服务端支持的个人计划及日期范围内，不把学校记录拖入个人排序接口。

| 必须区分 | 个人计划 | 学校作业 |
| --- | --- | --- |
| 时间 | 安排日期，可选开始/结束时间 | 截止时间或原文；可能未提供/未解析 |
| 完成 | 助手服务端 `Plan.done` | 本机完成集合；学校状态另行保留 |
| 修改能力 | 现有 UI 的新建、完成、排序、删除 | 本机标记和原站打开；不编辑学校记录 |
| 身份 | `plan:id` | `task:source:id` |
| 无时间 | 仍属于指定日期的计划，不画虚构时长 | 无截止与解析失败按现有原文/状态呈现 |

合并的是展示入口和清单，不合并数据库记录或完成语义。个人计划的安排日不自动改称截止日，本机勾选不改称“已提交学校”。加载、错误和空态分别保留两种来源的状态，不能因其中一路失败就显示“没有待办”。

原计划 API 虽有更新能力，当前 Plan UI 没有完整编辑入口；是否新增编辑不是等价移植的回归缺口，首版不据此扩大交互设计。

## 3. 保留的设计约束与暂缓事项

继续遵守 [DESIGN.md](../DESIGN.md) 与准备文档中的已采用设计原则：两套色系和浅深主题、清楚的中文与数字排版、真实时间比例、连续圆角与协调内缩、图形对应真实数据、关键文字可读、触控目标足够大。

首版将现有字段、内容顺序、主要动作、详情、筛选、空态和错误态转为 Compose；不以“原生化”为由删除旧能力或大幅改动信息密度。安全区、系统字体放大、键盘与返回需要原生适配，并纳入逐页对照。

暂缓：重写今天页叙事、将所有卡片改成另一种布局、重排校园各栏目、全局横向翻页、持续课程迷你播放器、新手势体系、大规模教学文案删改、脱离现有字段的新图表。后续可独立做第二版交互/密度实验，不和原生迁移的回归混在一起。

已发现与实际数据契约矛盾的旧文案不照抄，例如学校凭据的本机/服务端保存范围；按真实接口修正并单列必要差异，不趁机改服务端凭据策略。

## 4. 原生实现边界

最终 Android 的五个主页面、详情、表单、设置和状态均由 Compose 承载；Kotlin 直接访问现有 FastAPI，业务不再经过 React Store 或 Capacitor JS RPC。旧 JS 继续作为行为、数据解析和回归样本的依据，迁移期保留可运行对照。

```text
原生 Activity
└─ 主题 / 会话 / 返回与系统栏
   └─ Box
      ├─ 当前页面 NavHost + layerBackdrop（内容源）
      │  ├─ 今天 / 课表 / 事项 / 校园 / 我的
      │  └─ 原生详情、认证、导入等页面
      └─ Kyant 五项底栏（兄弟层，消费内容源）

Compose 页面 → ViewModel / StateFlow → Repository → 现有 FastAPI
                                            └─ 原生缓存 / 偏好 / 凭据保护
```

所有页面不必同时挂载成为兄弟；当前路由的内容源与浮动底栏为兄弟。底栏不进入自身采样源，不恢复 Bitmap 截图桥。详情与遮罩是否覆盖底栏沿用现有行为，避免内容、输入法和浮层重复占位。

材质继续使用已核对的 Kyant 原参数。完整原生客户端在低 API 上采用原生基础表面/模糊等能力档位，主导航和业务仍为 Compose；不能沿用当前过渡验证包“旧设备回 Web 导航”作为最终架构。

LastWave 参考状态分层、统一主题、列表稳定 key 和分组容器；不照搬其三导航、音乐栏目、按下即切页或小字排版。[本轮源码参考](#7-参考实现与依据)

普通按钮保留现有按下/释放两段触感；导航成功改变目的地一次 selection，重选或取消不增加反馈；唯一 0–100 强度设置保持。原生控件和业务层不重复播放。

## 5. 可保留的网页边界

学校原文、门户、水电等外部服务继续使用浏览器或 Custom Tabs。现有通知仅提供列表和原文链接，不凭空加入 HTML 正文抓取。登录、绑定 challenge、医学院连接和课表文件导入已有结构化接口，不能默认列为必须 WebView 的页面。

若同包升级需要读取旧本机偏好或作业勾选，可保留一次性、白名单式迁移工具；成功后按版本标记，不在每次启动保留一个隐藏常驻 WebView。最终核心路径与 APK 业务页面不依赖打包的 React 资源。

网页版/PWA 的现有入口先保留，避免 Android 重写同时破坏其他客户端；这不要求继续在 Android 中维护一套隐藏 JS 业务实现。

## 6. 实施顺序与完成口径

| 顺序 | 实施内容 | 验收条件 |
| --- | --- | --- |
| 1 | 固定功能对照表、接口样本与当前 APK 参照 | 每项既有能力都有原生目标和状态，不只记录主页面。 |
| 2 | 原生壳、五导航、主题/形状/触感、会话/HTTP/资源状态 | 页面和底栏共用 GPU 树；认证、来源状态与错误能独立呈现。 |
| 3 | 登录/绑定、今天、课表、课程详情和来源同步 | 真实只读流程、图码/QR/TOTP、缓存、未排定、重连、账号切换对齐。 |
| 4 | 事项：个人计划与学校作业合并，考试与成绩原生移植 | 日期/截止/完成语义保留；个人写入失败可恢复，不重复创建；考试成绩仍完整可达。 |
| 5 | 校园、我的、医学院、导入、更新及所有辅助入口 | 逐页功能对照全齐，外部学校入口仍可使用。 |
| 6 | 本机数据升级迁移、完整回归、移除过渡业务 WebView | 同包/兼容签名升级不丢勾选与设置；主流程不创建 WebView，不再打包 Android 的 React 业务界面。 |

中间包标为迁移预览。只有完整对照表全部完成并通过验收，才能称为全原生 V1；不能以五个标签能打开、其他页留空或仅有演示数据替代功能完成。

关键契约：业务时间固定 `Asia/Shanghai`；保留 13 节时刻、学期/周次、partial/pending/unarranged、考试时间原文与成绩估算规则。缓存按服务器与账号隔离，旧会话响应不得污染新会话；学校重连失败不清掉助手登录。创建/导入等写请求不盲目自动重放。

迁移清单包含主题、色系、触感强度及本机作业完成集合；服务端个人计划重读。普通 DataStore 不能冒充加密存储，token与保留的本机凭据使用 Keystore 保护。旧数据来源或账号归属不明时不自动并入当前用户。
